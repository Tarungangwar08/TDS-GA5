AI nahi:

1) receiptValidationPassed — signature ACTUALLY verify karni padti hai.
   Grader ek receipt ka `accepted` flag true se false kar deta hai aur baaki
   sab bindings (dossierId, callId, action, proposalDigest) same rakhta hai.
   Sirf binding check karoge toh woh forged receipt 200 le jayega.
   Aur jo message sign hota hai woh bare receipt NAHI hai — yahi sabse badi
   galti hai. Ye hai (recursively key-sorted compact JSON):
     {"profile","evaluationId","inputDigest",
      "receipt": <receipt ke saare fields except receiptSignature>}
   UTF-8 bytes, Ed25519, key = propose request ke receiptVerifier.publicKeyJwk.x
   ko base64url decode karke (32 bytes). Har run me nayi key aati hai, toh
   hardcode mat karna.

2) conflictPassed — conflict sirf EK CHARACTER ka hota hai.
   Grader wahi evaluationId dobara bhejta hai, dossiers bilkul same, bas
   receiptVerifier ki public key ka pehla character badal deta hai:
     "n5vtC0l_uZ52..." -> "A5vtC0l_uZ52..."
   Agar tum sirf dossiers compare karte ho toh ye exact replay lagta hai, tum
   200 de dete ho, aur feedback me bas "conflict rejection failed" aata hai.
   Fix: inputDigest ko dossiers ka digest hi rehne do (grader use commit pe
   wapas bhejta hai), aur ek DOOSRA content digest rakho jisme dossiers +
   corpus + allowedActions + profile + receiptVerifier sab ho — conflict usse
   detect karo.
